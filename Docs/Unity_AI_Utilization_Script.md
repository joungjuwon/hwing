# 영상 스크립트: 당신이 AI를 Unity에 제대로 활용 못하던 이유

(Youtube: [RhcDFMZnP4w](https://www.youtube.com/watch?v=RhcDFMZnP4w))

## 1. 왜 그동안 AI를 제대로 활용하지 못했는가?

많은 개발자들이 AI에게 코딩을 시킬 때 실패하는 이유는 크게 세 가지입니다.

### ❌ 1. 맥락(Context)의 부재
유니티는 엔진 버전, 렌더링 파이프라인(URP/HDRP/Built-in), 사용하는 패키지(Input System 등)에 따라 코드가 완전히 달라집니다.
AI에게 "캐릭터 점프 코드 짜줘"라고만 하면, AI는 가장 일반적인(구버전일 수도 있는) 코드를 던져줍니다. 이는 내 프로젝트 설정과 맞지 않아 에러를 유발합니다.

### ❌ 2. 잘못된 질문 방식
구현하려는 기능의 '목적'이나 '설계'를 묻지 않고, 단순히 '결과물' 코드만 요구합니다.
예를 들어 "적 이동 코드 줘"라고 하기보다는, "어떤 패턴을 써야 효율적인지"를 먼저 물어야 합니다.

### ❌ 3. 검증 단계 생략
AI가 생성한 코드가 유니티의 생명주기(Life Cycle)나 물리 엔진 연산(FixedUpdate 등)과 충돌하지 않는지 검토하지 않고 복붙합니다.

## 2. AI를 제대로 활용하기 위한 3가지 핵심 전략

### ✅ 전략 1: 컨텍스트 주입 (Context Injection)
질문을 시작하기 전에 내 프로젝트의 환경 정보를 "선언"해야 합니다.

*   **프롬프트 예시:**
    > "나는 Unity 2022.3 버전을 사용 중이고, URP 파이프라인과 New Input System을 쓰고 있어. DOTween 라이브러리도 사용 가능해. 이 환경에서 다음 코드를 작성해줘."
*   **구조 공유:** 기존에 작성된 `PlayerController`나 `IEnemy` 인터페이스 코드를 먼저 보여주고, "이 구조를 상속받거나 참조해서 작성해줘"라고 해야 일관성 있는 코드가 나옵니다.

### ✅ 전략 2: 단계별 지시 (Chain of Thought)
한 번에 완벽한 코드를 얻으려 하지 말고, 사고의 과정을 단계별로 나눕니다.

1.  **설계 요청:** "FSM(유한 상태 머신)으로 적 AI를 만들 건데, 상태를 어떻게 나누면 좋을까?"
2.  **검토:** "그 상태들이 꼬이지 않게 전이 조건은 어떻게 설정할까?"
3.  **코드 작성:** "위 설계에 맞춰서 C# 스크립트를 작성해줘."
4.  **최적화:** "이 코드에서 가비지 컬렉션(GC)이 발생할 부분이 있어?"

### ✅ 전략 3: IDE 환경과의 결합 (Cursor, Copilot)
웹사이트(ChatGPT/Claude)를 왔다 갔다 하는 것은 흐름을 끊습니다.
**Cursor**나 **GitHub Copilot** 같은 AI 통합 IDE를 사용하면, AI가 내 프로젝트의 전체 파일과 클래스 구조를 '인덱싱'하여 이해합니다.
"이 변수(`playerHealth`)를 참조해서 UI를 업데이트해줘"라고 하면, AI가 알아서 해당 변수의 위치를 찾아서 코드를 짜줍니다.

## 3. 실질적인 활용 팁

*   **에러 해결:** 단순히 에러 로그만 보여주지 말고, 에러가 난 코드의 앞뒤 문맥(20줄 정도)을 같이 주면서 "논리적으로 어떤 문제가 있는지" 물어보세요.
*   **리팩토링:** "이 스파게티 코드를 `ScriptableObject`를 활용한 데이터 주도 설계로 바꿔줘"와 같이 구체적인 디자인 패턴을 요구하면 학습 효과도 큽니다.
*   **전용 툴 활용:** Unity Muse나 Sentis 같은 유니티 특화 AI 도구를 활용하면 텍스처 생성이나 런타임 AI 기능 구현도 수월해집니다.

---

### 💡 결론
AI는 '코드 자판기'가 아니라 **'내 프로젝트를 전부 알고 있는 수석 파트너 개발자'**입니다. 
그에게 충분한 정보를 주고(Context), 같이 고민하고(Chain of Thought), 작업 환경을 일치시켜야(IDE) 비로소 5배, 10배의 생산성을 얻을 수 있습니다.
